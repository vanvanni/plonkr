Three steps. You already do the first one.

Plonkr doesn’t change how you create machines. It starts when you’re done.

  1. Make the machine

    Container, VM or a box on a shelf. Use whatever you use today.

  2. Reach it over SSH

    Plonkr connects to the machine that’s already there, the way you would from your own terminal.

  3. Put the setup in place

    Updates, the usual tools, your working environment. The same result each time, then back to your actual work.

What it is, and what it isn’t.

Plonkr is early, so it’s worth being clear about the edges.

It is

  • For machines that already exist. Containers, VMs and bare metal.
  • Used over SSH. It meets your machines where they already are.
  • Aimed at the first-hour chores. Updates, the usual tools, your working environment.
  • One command: plonk.

It isn’t

  • A way to create machines. Keep using whatever you use now.
  • Stable. It’s a beta. You can install the latest prerelease, but interfaces may change.
  • Decided. Command syntax, config format and supported platforms wait for the proof of concept.
