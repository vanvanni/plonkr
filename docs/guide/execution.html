Execution and results

Understand what will run and what actually happened.

Plonkr expands profiles and snippets before executing a sequential plan over SSH. It checks argument contracts, collects all profile answers, then validates the fully resolved plan before connecting. Supply repeatable --arg name=value options for unattended runs. Dry runs also resolve inputs; validate never prompts and reports unresolved required inputs.

Preview before applying

The prototype's dry run validates and expands configuration without connecting to SSH or reading repository key files. It renders unit templates and shows selected and skipped work. A preview is a plan, not evidence that credentials, privileges or remote dependencies will work.

The final Plonkr preview command and flags are not settled yet.

Result meanings

  • Completed: intended to mean that the action executed successfully.
  • Failed: intended to identify an action that encountered an error.
  • Skipped: the prototype uses this for work gated by a disabled flag; the new contract is still being finalized.
  • Ignored or bypassed: required as a distinct concept; behavior and naming are awaiting definition.

These are interface goals, not a released status contract. Previewed work, cancellation and work never reached after failure also need distinguishable results. Bypass must not be assumed to mean “ignore errors and continue”; continuation and exit-code rules have not been decided.

Failure and repeat runs

The prototype stops at the first failure. It has no retries, rollback or automatic resume. A failed operation may leave partial changes on the target. Existing repository destinations fail rather than being updated or verified.

Each shell item uses a separate remote shell: a cd or variable assignment in one item does not carry into the next. Keep dependent shell operations together. Cancellation stops local SSH but cannot guarantee that every remote descendant stops.

These limits describe the prototype; v2026.11.0 repeat-run and recovery behavior must be agreed and verified before becoming a release guarantee.

Output and logs

The prototype offers a terminal screen and plain output. Runs that reach execution logging save commands and combined stdout/stderr in a private log. Earlier loading failures may occur before a log is created.

Commands and their output can contain sensitive data. Terminal escape stripping does not redact secrets. The new log location, retention and exact output format are not finalized.

Platforms and privileges

Managed prototype operations assume Linux tools; unit installation assumes systemd. Provisioning requires the appropriate target-user permissions, root or noninteractive sudo. Profiles execute trusted shell code with those privileges.

The intended machine types are containers, VMs and bare metal. That does not imply support for every operating system. Windows profile storage is agreed, while Windows controller behavior and the first supported target systems still need verification.
