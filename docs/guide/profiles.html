Profiles and locations

Keep setup instructions on the machine where you run plonk.

A profile describes setup for a target. A snippet is reusable work included by a profile. A template supplies the content of a managed file such as a service unit. Profiles may live in subfolders; snippets and templates live in their own directories beneath the profiles root.

Windows profile location

Default location: %ProgramData%\plonkr\. Resolve %ProgramData% on the controller rather than hard-coding a drive letter. This is machine-wide storage, not a separate directory for each Windows user.

Create this directory and your profiles with the permissions appropriate for your machine. Plonkr does not migrate the prototype's Documents directory automatically.

Linux profile location

Default location: /etc/plonkr/. This machine-wide directory may require elevated permissions to create or edit.

Moving existing profiles

Pass --profiles-dir to select a profiles root, or set PLONK_PROFILES_DIR to an absolute path. The flag takes precedence over the environment variable, which takes precedence over the platform default. No automatic migration from Documents is implemented.

Existing prototype profiles use a different schema from the current beta examples. Moving a file alone will not make it compatible. Keep the original profile while adapting it to the final format.

Names such as web and proxmox/lab resolve from the selected profiles directory, with .hcl implied. Each slash-separated segment starts with a letter, digit or underscore and continues with letters, digits, underscores or hyphens (ASCII). Names allow at most 255 bytes and eight segments. The first segment cannot be snippets or files; empty, hidden and traversal segments and backslashes are invalid.

An absolute reference, one containing a backslash, ending in .hcl, or starting with ./ or ../ is a file path. Paths load exactly that file: web.hcl no longer falls back to the profiles directory. Use web for a name, proxmox/lab for a nested name, and ./proxmox/lab for an extensionless relative path.

Includes always resolve from the profiles root, regardless of the including file's subfolder. Snippets stay flat in snippets/ and templates live in files/ under that root. A profile selected by path uses its own directory as the dependency base unless --profiles-dir is supplied. Prefer names for profiles in subfolders, or pass the profiles root explicitly alongside a path. Dependencies load before execution; unrelated profiles are not executed.

Local paths and target paths

A repository key source is a path on the controller. The repository checkout path and the installed key path are on the target. A Windows controller may therefore reference a Windows key file while preparing a Linux target.

Private key material belongs in the source key file, not inside a profile. Native Windows source-path handling must be verified before the Windows workflow is documented as supported.
