Machine setup with Plonkr

Prepare a machine you already have, using a profile that describes its setup.

Plonkr is the product; plonk is the command. It configures existing containers, VMs and bare metal that you can reach over SSH. Creating the machine stays with your existing tools.

Read this first

Beta — no stable release yet: these pages describe 2026.11.0-beta.5. The profile format and commands work as documented, but interfaces may still change before the first stable release. Check the release notes when you upgrade.

Plonkr runs through your local OpenSSH client and needs no agent on the target. Managed operations target Linux, and unit installation needs systemd. The full real-SSH acceptance suite runs on Ubuntu 24.04 from a Linux controller. Native Windows SSH transport and Linux arm64 at runtime have not been verified yet.

The workflow

  1. Create your target machine and make sure ssh HOST works.
  2. Describe users, groups, repositories, units and ordered tasks in a profile.
  3. Check it offline with plonk validate PROFILE, then preview the expanded plan with plonk run HOST PROFILE --dry-run.
  4. Apply it with plonk run HOST PROFILE and read the results on screen or in the saved run log.
plonk validate web
plonk run my-host web --dry-run
plonk run my-host web

Installation

Plonkr is one executable, plonk, built for Linux (amd64, arm64) and Windows (amd64). It uses the OpenSSH client already on your machine. There is no stable release yet: the scripts below install the newest GitHub release, prereleases included, and interfaces may change before stable.

On Linux:

curl -fsSL https://plonkr.dev/install.sh | sh

On Windows, in PowerShell:

irm https://plonkr.dev/install.ps1 | iex

Both scripts download the release archive, check it against the release's SHA256SUMS and install only plonk. Nothing else on the machine changes. Linux installs to /usr/local/bin as root and to ~/.local/bin otherwise. Windows installs to %LOCALAPPDATA%\Programs\plonk for the current user, without administrator rights, and adds that folder to your user PATH. Read the scripts first if you like: install.sh and install.ps1.

Choose a version or folder, or remove Plonkr again:

# Linux
curl -fsSL https://plonkr.dev/install.sh | sh -s -- --version 2026.11.0-beta.5
curl -fsSL https://plonkr.dev/install.sh | sh -s -- --dir ~/bin
curl -fsSL https://plonkr.dev/install.sh | sh -s -- --uninstall

# Windows (PowerShell)
$env:PLONK_VERSION = '2026.11.0-beta.5'; irm https://plonkr.dev/install.ps1 | iex
$env:PLONK_INSTALL_DIR = 'D:\Tools\plonk'; irm https://plonkr.dev/install.ps1 | iex
$env:PLONK_UNINSTALL = '1'; irm https://plonkr.dev/install.ps1 | iex

Check the result with plonk version. To build from source instead, see the repository README.

Verification: the installers were run against a local copy of the release layout on Ubuntu 22.04 (curl and wget) and in Windows PowerShell 5.1 and 7, including checksum mismatch, wrong version, reinstall and uninstall. They have not been run against a published release, and macOS is not supported.

Command reference

CommandWhat it does
plonk validate PROFILEParse and validate a profile and print the expanded plan. Fully offline and never prompts. Accepts --profiles-dir DIR and repeatable --arg NAME=VALUE; with required arguments missing, it checks argument contracts and lists the missing inputs instead.
plonk run HOST PROFILEExecute a profile over SSH. HOST is an SSH alias or user@host.
plonk run PROFILEExecute a controller-only profile (plugin, wait() and log() steps only) without a host.
plonk versionPrint the CLI version.
plonk run optionWhat it does
--dry-runCollect inputs and show the plan without SSH or reading deploy keys. Plugin objects may be read from their API, never changed.
--arg NAME=VALUESupply a profile argument (repeatable). Without it, a terminal run asks the profile's questions first.
--bypass NAMEBypass every task with this exact, case-sensitive name (repeatable).
--forceRun tasks even when their lock would bypass them.
--auto-approveApprove deploy-key replacement and destructive plugin actions without prompting. It does not answer argument questions.
--profiles-dir DIRUse another profiles root.
--no-tuiPlain streaming output instead of the terminal screen.
--ttyAllocate a remote terminal for interactive prompts; disables the terminal screen.
--NAMEEnable steps gated by flag("NAME", ...) in the profile. plonk run HOST PROFILE --help lists them.

The repository's CLI guide covers every option and edge case in detail.

Road to v2026.11.0

The agreed v2026.11.0 scope is implemented: automatic account creation with explicit opt-out, direct deploy-key copying (the private-key store is gone), profiles in /etc/plonkr/ or %ProgramData%\plonkr\, and distinct result states. Betas since then added typed arguments, task locks, waiting steps, subfolder profiles and the plugin framework.

Before a stable release, the remaining checks are native Windows SSH transport, Linux arm64 at runtime and the installers against a published release. A successful key copy alone is still not evidence of a successful private repository clone; see what a clone requires.
