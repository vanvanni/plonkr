Machine setup with Plonkr

Prepare a machine you already have, using a profile that describes its setup.

Plonkr is the product; plonk is the command. The intended workflow covers existing containers, VMs and bare metal reached over SSH. Creating the machine stays with your existing tools.

Read this first

Beta documentation — no stable release yet: the proof of concept has been reviewed, but Plonkr is installable only as a beta prerelease. These pages distinguish agreed v2026.11.0 behavior from proposed syntax and capabilities seen in the prototype. Examples are design examples, not commands to run against a released binary.

The initial prototype implements ordered SSH execution, profile composition, conditional steps, account setup, repository cloning and systemd unit-file installation. That is implementation evidence, not a guarantee of supported platforms or reliable reruns in the prerelease.

The workflow

  1. Create your target machine and establish SSH access.
  2. Describe users, groups, repository access and setup work in a local profile.
  3. Review the expanded plan before applying changes.
  4. Run setup and inspect the results and log.

The preview and execution workflow exists in the prototype. The final command grammar and platform support are still being agreed.

Installation

Plonkr is one executable, plonk, built for Linux (amd64, arm64) and Windows (amd64). It uses the OpenSSH client already on your machine. There is no stable release yet: the scripts below install the newest GitHub release, prereleases included, and interfaces may change before stable.

On Linux:

curl -fsSL https://plonkr.dev/install.sh | sh

On Windows, in PowerShell:

irm https://plonkr.dev/install.ps1 | iex

Both scripts download the release archive, check it against the release's SHA256SUMS and install only plonk. Nothing else on the machine changes. Linux installs to /usr/local/bin as root and to ~/.local/bin otherwise. Windows installs to %LOCALAPPDATA%Programsplonk for the current user, without administrator rights, and adds that folder to your user PATH. Read the scripts first if you like: install.sh and install.ps1.

Choose a version or folder, or remove Plonkr again:

# Linux
curl -fsSL https://plonkr.dev/install.sh | sh -s -- --version 2026.11.0-beta.2
curl -fsSL https://plonkr.dev/install.sh | sh -s -- --dir ~/bin
curl -fsSL https://plonkr.dev/install.sh | sh -s -- --uninstall

# Windows (PowerShell)
$env:PLONK_VERSION = '2026.11.0-beta.2'; irm https://plonkr.dev/install.ps1 | iex
$env:PLONK_INSTALL_DIR = 'D:Toolsplonk'; irm https://plonkr.dev/install.ps1 | iex
$env:PLONK_UNINSTALL = '1'; irm https://plonkr.dev/install.ps1 | iex

Check the result with plonk version. To build from source instead, see the repository README.

Verification: the installers were run against a local copy of the release layout on Ubuntu 22.04 (curl and wget) and in Windows PowerShell 5.1 and 7, including checksum mismatch, wrong version, reinstall and uninstall. They have not been run against a published release, and macOS is not supported.

Command reference

The executable name is plonk. Its subcommands and flags are not finalized. The landing-page terminal is illustrative; it is not a command reference.

Road to v2026.11.0

The agreed priorities are cleaner configuration, reliable repository-key copying, relocation of profile storage and clearer execution results. The private-key store will be removed. Users and groups will support automatic creation with explicit opt-out.

Before release, the configuration grammar, supported systems, repeat-run behavior and bypass semantics need to be finalized and tested. A successful key copy alone is not evidence of a successful private repository clone.
