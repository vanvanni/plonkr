Configuration and tasks

Describe the machine's accounts separately from its ordered setup work.

Behavior versus syntax: automatic user/group creation and the explicit opt-out are agreed. The HCL structure and helper names shown here are proposals and are not accepted by the current prototype parser.

Automatic and explicit creation

Users and groups declared in configuration are automatically created on first run unless create = false. The same rule applies to both resource types.

create = false means “do not create automatically.” An explicit setup call can still create that resource at the chosen point in a task. It does not mean that the resource can never be created.

Existing-resource checks and subsequent-run behavior still need to be defined. First-run creation does not imply a global “already configured” marker.

Users and groups

The draft user model includes a name, service-account designation, supplementary groups and SSH public keys. Groups can have a name and an optional numeric GID. Exact defaults and conflict rules remain under discussion.

configuration {
  groups = [
    { name = "app" },
    { name = "reports", create = false },
  ]
  users = [
    { name = "app", service = true, groups = ["app"] },
    { name = "reporter", service = false, groups = ["reports"], create = false },
  ]
}

Proposed HCL example: app is automatically created. The reports group and reporter user wait for explicit setup operations. Public keys grant login access; repository private keys serve a different purpose.

Named tasks and phases

The draft proposes named tasks with a numeric order. A task can contain managed setup operations, a shell script, or both. Within a task, setup would run before script regardless of attribute placement.

tasks {
  task "Prepare reports account" {
    order = 10
    setup = [group("reports"), user("reporter")]
    script = ["echo reports-account-ready"]
  }
}

Proposed syntax: group() and user() are managed setup helpers. Shell commands belong in script. The proposed phase boundary prevents managed setup helpers from appearing in script and shell commands from appearing in setup.

Ordering still to finalize

The proposed baseline order is automatic groups, automatic users, then ordered tasks. It has not yet been approved. Task-order ties, dependencies on explicitly created groups, and what happens when setup fails before script also need final rules.

Timezone configuration, unit installation, local messages, conditions and profile inclusion need defined placement in the new structure. Their prototype behavior does not settle their new-format behavior.
